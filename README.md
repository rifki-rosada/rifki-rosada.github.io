# Rifki Rosada Portfolio

Static, conversion-focused portfolio optimized for GitHub Pages + custom domain deployment.

## Stack and Architecture

- Static HTML output generated by a local build script.
- Central content model: `content/site-data.json`.
- Shared UI system:
  - `assets/css/site.css`
  - `assets/js/site.js`
- Static generator:
  - `scripts/build-site.mjs`

The build script renders:

- `/` (Home)
- `/work/` (all case studies)
- `/work/<slug>/` (case study details)
- `/hire/`
- `404.html` and `/404/`
- legacy redirects: `/projects/`, `/experience/`, `/contact/`
- `sitemap.xml`, `robots.txt`, `site.webmanifest`

## Local Development

1. Install Node.js 18+ (Node 24 is used in this repo).
2. Build site output:
   - `npm run build`
3. Optional validation run:
   - `npm run check`
4. Preview locally with any static server (for example VS Code Live Server).

## Build and Deployment (GitHub Pages + Custom Domain)

Current configuration is custom domain root (`CNAME` = `rifkirosada.com`), so links and canonical URLs are generated for root hosting.

1. Run build:
   - `npm run build`
2. Commit generated files.
3. Push to the branch used by GitHub Pages.
4. In GitHub repository settings:
   - Pages source points to this repository output (root/static branch flow).
   - Keep `CNAME` committed.
   - Keep `.nojekyll` committed.

## Content Editing Guide

Update these sections in `content/site-data.json`:

- Hero and proof strip: `site`, `proofStrip`
- Services and pricing: `services`, `retainer`
- Contact methods: `contact`
- Work process and scope template: `workProcess`, `scopeTemplate`
- Case studies (cards + detail pages): `caseStudies`

After editing content:

1. Run `npm run build`
2. Commit changes
3. Deploy via GitHub Pages
