IndoGate Monorepo - Admin, Landing, and API

Consolidated product surfaces into a monorepo architecture with Next.js frontend apps and a NestJS API.

Architecture Case Study

Problem

Separate repositories for dashboard, landing page, and backend API created dependency drift and release overhead.

Constraints

  • Multiple app surfaces needed independent delivery while sharing core standards.
  • Team workflows required clear boundaries between frontend apps and backend services.
  • Tooling had to stay simple for contributors using npm workspaces.

Approach

  • Structured the project using npm workspaces with dedicated app and service packages.
  • Standardized scripts and conventions for local development and CI-friendly execution.
  • Implemented Next.js AdminDashboard, Next.js Landing, and NestJS API within one coordinated repository.

Result

  • Reduced release friction across related surfaces by unifying repository management.
  • Improved consistency in dependency updates and shared engineering conventions.
  • Enabled more predictable collaboration between product and engineering contributors.

Tech Stack

  • npm workspaces
  • Next.js
  • NestJS
  • TypeScript
